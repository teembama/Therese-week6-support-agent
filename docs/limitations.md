# Known Limitations and Future Work

Known limitations of the submitted system, and what we would do next. Details are in `docs/decisions.md` (D-numbers).

## Limitations

| Area | Limitation | Why it's accepted now | Future work |
| --- | --- | --- | --- |
| Web voice page | `@vapi-ai/web` **2.7.1** (the latest, published 2026-09-18) pins **`@daily-co/daily-js ^0.87.0`** (published 2026-01-29). Chrome warns that "daily-js version 0.87.0 is nearing end of support". Daily is at 0.92.2 (checked 2026-09-30), and **no published Vapi SDK version uses a newer daily-js**. | The pinned pair works once the CSP allows what Daily needs (D55). Changing the transport right before submission is riskier than the warning. | Watch for a Vapi SDK release on a supported daily-js, then upgrade both pins together and re-run a live call. Don't override Daily's version under the SDK: it's untested against it. |
| Web voice page | The CSP allows `'unsafe-eval'` and `blob:` in `script-src`, because Daily's bundle and its Krisp worklet need them (D55). | There are no inline scripts, no user-generated content, pinned sources and a short source list. | Drop both if a Daily/Vapi release stops needing eval or blob: worklets. |
| CSP visibility | Our `/csp-report` route recorded the eval block, but **not** the `blob:` worklet block (that one was seen only in Chrome's console). | The console gave the evidence. | Add the `Reporting-Endpoints` / `report-to` header, and check whether worklet violations are reported there. |
| Grounding | The runtime filter drops **whole sentences** (D37), with two exceptions. An invented "your" whose remainder is verbatim evidence is removed (D62). A flagged trailing clause after ", so / which / meaning / —" is cut when the leading clause passes every check (D64). Every other flag still drops the sentence. | A lost sentence is safer than a spoken unsupported claim. | Measure how often a correct sentence is dropped in the Task 6 evals. Consider one targeted retry ("rephrase without …") before falling back to decline. |
| Grounding (G1) | In an **answer** citing a valid chunk, a **number-free** unsupported claim can be spoken ("your payment is most likely held up by bank processing times"). Pattern checks can't catch meaning added without their markers. Decline, clarify and escalate replies are covered by the diagnosis check (D58). | The backstop is the **offline LLM judge**, built in `scripts/eval-scenarios.ts` (Sonnet 5.5 with code-verified quotes, D66). It caught this pattern in S8 (docs/testing-evidence.md). A runtime judge was considered and rejected for latency: about +0.6–1.2 s before any answer is spoken, and no sentence streaming. It would cost ≈ $0.0012 per answer (+40%) (D63). | Build the offline judge, run it on every scenario several times, and revisit a runtime judge if it finds these claims often. |
| Identity (F2) | A first name plus a company name verifies a caller ("Amara from LagosLedger"). | Required by Scenario 3's own wording. Verification unlocks no sensitive data: never an amount, currency, email or notes (D40, D63). | Require a non-public identifier for anything beyond status; flag escalations whose email differs from the account's. |
| References (F1) | TXN/PAY lookups work before verification, and there is **no rate limit on enumerating references** (4-digit IDs). | Required by Scenario 4. Only the safe summary is returned: no amount, currency, customer or recipient (D44, D63). | Cap distinct references looked up per unverified conversation. |
| Retrieval | The crypto question (X1) doesn't retrieve its answer chunk (D17). | It's a known lexical-retrieval gap and is documented. | Add synonyms or embeddings. |
| Scaling | Identical concurrent retries are joined in-process, which is correct only while **one instance** serves a call (D29). | We deploy one replica. | Route by call ID, or move the in-flight map to shared state, before scaling out. |
| Write caps | The per-conversation cap (2 tickets, 1 escalation) is counted in the tool, not enforced by a database constraint (D43). | Writes within a turn are serialised, and a replaced attempt can't write. | Add a database constraint or trigger (a migration). |
| Model | Claude Haiku 4.5 has a retirement floor of **2026-10-15**. It is mitigated by the env-only model choice and an automatic fallback on `model_not_found` (D49). | The deprecation status is checked before grading (checklist). | Move to the successor model once it's measured. |
| Vapi metrics | The units of `performanceMetrics`, and whether it is always present, aren't fully documented (D50). | Stored as received, with `null` when absent. | Confirm against real calls. |
| Team notifications | The Discord sender (D83) delivers at most once: a row interrupted mid-send is marked failed, not resent. Delivery is best-effort with one retry. Rows from `test` conversations are never posted. | No double posts; a missed message is visible in `notification_outbox` (failed, with `last_error`). | Add an alert on failed rows, and an operator "resend" action. |
| Customer confirmations | The caller gets no email confirming the ticket or escalation; only the team is notified (D83). | Out of scope for this week. The outbox is built so another notification kind can be added. | Add a `customer_confirmation` outbox kind with a transactional email provider and a verified sender domain. |
| Identity (F1/F2) | Callers are identified by voice only (name plus company, or a reference). | See the F1 and F2 rows above. | **Authenticated login sessions:** the web page signs the customer in, and the call carries their verified identity, replacing the weak voice identity. |
| Hosting config | Railway's config-as-code (`railway.json`) is deprecated and keeps working until 2026-12-01. The first deploy also ignored its region (D53). | The region was fixed with `railway scale`, and the file still states it. | Migrate to `.railway/railway.ts`. |
